# Local LangGraph Agent

Both `/rag/assistant/query` and `/rag/query-by-document` now use the Agent by
default. The server resolves persisted history and the current document before
running a request-local StateGraph:

```text
START -> agent -> tools -> agent -> ... -> END
                    |
                    +-> finalize (budget exhausted) -> END
```

LangChain binds StructuredTools to Gemini. LangGraph appends the original model
messages and matching ToolMessages, preserving Gemini thought signatures. The
existing `gemini-3.5-flash` model setting is retained. The older Google integration
2.1.8 failed a live multi-turn tool test because it discarded those signatures;
the local stack now uses langchain-google-genai 4.4.0, LangChain 1.4.0 and
LangGraph 1.2.11. Legacy RetrievalQA imports were migrated to langchain-classic.

References: [LangGraph tool loop](https://docs.langchain.com/oss/python/langgraph/quickstart),
[Gemini integration and signatures](https://docs.langchain.com/oss/python/integrations/chat/google_generative_ai).

## Configuration and startup

```dotenv
QUERY_ENGINE=agent
AGENT_MAX_ROUNDS=4
AGENT_MAX_TOOL_CALLS=6
AGENT_TIMEOUT_SECONDS=180
AGENT_TOP_K=5
STORAGE_BACKEND=local
DOCUMENT_PROCESSING_MODE=sync
DATABASE_BACKEND=sqlite
```

Install `requirements.txt` in the project environment, then start the backend
and frontend in separate terminals from the project root:

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
python -m streamlit run frontend.py
```

Set `QUERY_ENGINE=legacy` and restart the backend to use the earlier classifier
pipeline with the current dependency stack. AWS configurations and
`requirements.ecs.txt` remain historical files; they are not a deployment recipe
for this Agent version.

## Tools and permissions

- `document_search(query)`: bound to the server-resolved current session/document.
  Calls return retrieved excerpts and existing metadata. The model cannot supply
  paths, session IDs, or document IDs.
- `conversation_history()`: reads the server's persisted snapshot. Strict mode
  only exposes document-linked turns marked as document/history sources, excluding
  general and mixed web answers. This deliberately limits history across modes.
- `web_search(query)`: only bound in Assistant mode when web search is enabled.
  Gemini native grounding remains a separate model call inside this tool.

Execution rejects unregistered tool names and validates arguments. Limits count
tool attempts, including failures. At the budget boundary the graph makes at most
one final model call without tools. A wall-clock timeout returns HTTP 504 and does
not save an answer; provider/model failures return HTTP 502. Cancelling the graph
cannot forcibly terminate a synchronous SDK/retrieval call already running in a
worker thread, but that work cannot save a late answer through this request.

## Response compatibility

Existing answer/source fields remain available. New fields are:
`execution_engine`, `agent_steps` (tool names/status only), `agent_limit_reached`,
and `document_sources` (retrieved evidence, not proof of sentence-level citation).
The frontend displays these after the response; this is not token streaming.

Categories now describe observed tool use, not an initial classifier decision.
Assistant-mode document retrieval is conservatively labeled HYBRID because general
explanation is allowed. Strict retrieval uses DOCUMENT. Document/history evidence
combined with a web attempt is DOCUMENT_AND_WEB, with search success reported
separately. Document-linked results still follow replacement rules.

Google grounding spans belong to the intermediate search answer, so their
`cited_text` is cleared before displaying sources for the final synthesized answer.
URLs are taken from provider metadata, not generated by the final model.

SQLite continues to save final answers, categories and web sources. Agent tool
steps and document excerpts are response-only and are not restored after a page
restart. There is no persistent graph checkpoint or interrupted-run resume yet.
PDF parsing and existing FAISS indexes are unchanged; old indexes do not gain page
numbers automatically. Anonymous session scoping is still not authentication.

## Verification

```bash
# Offline, disposable SQLite and scripted models; no paid calls
python -B -m unittest discover -s tests -v

# Opt-in live Gemini test: synthetic history only, no user document access
python -B tests/live_agent_smoke.py
```

The live smoke verifies model -> history tool -> model using the configured Gemini
model. Offline tests additionally exercise document-plus-web execution, permission
denial, budgets, timeouts, failures, history scoping, and API persistence. Full real
PDF/search quality still requires representative end-to-end evaluation.

Validated in `rag_llm`: 25 offline tests passed, the live Gemini history-tool loop
passed, the standalone live Google Search check returned grounding sources, and
`pip check` reported no broken requirements. Installing the local requirements
with `--dry-run` also resolved successfully in this environment.
